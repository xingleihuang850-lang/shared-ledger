## 账本 PWA 代码审查修复

用户提交一份详尽的 17 项代码审查报告，按优先级完成以下修复（均在 `app.js` / `index.html` / `README.md`）：

### 正确性（致命 bug）
- **settings keyPath**：`openDB` 原给全部 7 个 store 统一 `keyPath:'id'`，但 settings 记录是 `{key,value}`，put 抛 DataError 静默失败。改 `settings` 用 `keyPath:'key'`，DB_VER 5→6，onupgradeneeded 中删除重建旧 settings store（旧库恒空，安全）。
- **月度定期跨二月**：`_nextDate` monthly 原 `setMonth(+1)` 使 1/31 溢出到 3/3 跳过 2 月。改为先 `setDate(1)` 再 `setMonth(+1)` 再 clamp。
- **定期项首次触发日**：新增 `_firstMonthlyDate()`，monthly 项 startDate 按设定的 dayOfMonth 计算（本月已过则顺延下月），不再从创建当天触发。

### 数据完整性
- **备份补全**：`exportData`/`importData`/`collectAllData`/`pullSync` 均补上 badges/wishes/recurring 三个 store（此前丢 recurring）。
- **真清空**：`clearAll` 清空全部 7 个 store，并重建默认分类 + 默认用户 u1，重置 currentUser。
- **兜底分类**：CSV 导入未识别分类 id `e99`（不存在）→ `e10`（其他），不再静默归到餐饮。

### 安全
- **导入 id 转义**：新增 `jsId()` helper（JSON.stringify + escapeHtml），所有内联 onclick 传 id 处（switchUser/selectCat/editCatIcon/delCategory/toggleRecurring/deleteRecurring）改用 jsId，`data-txn-id` 用 escapeHtml，防恶意备份文件注入。

### 逻辑修正 + 体验
- **多用户隔离**：badges 加 `userId`/`badgeId` 字段（id 用 `${userId}_${badgeId}`），wishes 加 `userId`，读取均按当前用户过滤（旧无 userId 数据视为 u1）。
- **徽章判定**：`streak_7` 改为统计所有交易（含收入）日期；`no_dining` 改为只对「上月」（已结束月份）判定。
- **交易编辑**：`_onTxnClick` 从「confirm 删除」改为打开新增的 `editTxnModal`（金额/日期/类型/分类/备注 + 保存/删除），新增 `openEditTxn`/`editSetType`/`saveEditTxn`/`confirmDeleteTxn`。
- **愿望进度注明**：renderWishes 顶部加说明「进度按当前用户总存款独立计算」。

### 文案/CDN

- Leaflet 从 unpkg 统一到 jsdelivr，与 SW 离线缓存分支一致。
